# Repository Guidelines

## Проект и структура

Это статический одностраничный сайт вымышленной маникюрной студии «Ягода». `index.html` содержит семантическую разметку и тексты, `styles.css` — адаптивное оформление, `script.js` — каталог, профили мастеров, календарь, отзывы и интерактивность демо-записи, `assets/hero.png` — иллюстрация первого экрана, `assets/logo.svg` — знак бренда и favicon. Внешние пакеты, сборщик и тестовый фреймворк не используются. Портфолио нарисовано CSS-иллюстрациями; не добавляйте их как реальные фотографии работ.

## Эталон для новых демо

Для новых демо-сайтов других сервисов в этом репозитории используйте `yagoda-copy/` как основную стартовую и эталонную реализацию. Не берите за основу старые корневые `yagoda.html`, `styles.css` и `script.js`, если пользователь отдельно этого не попросил. Сохраняйте в новых демо тот же уровень цельности и готовности: чистая семантическая разметка, дизайн-токены, адаптивная вёрстка, локальные/оптимизированные ресурсы, доступные состояния и законченные интерактивные сценарии. Переносите подход и проверенные общие решения из `yagoda-copy`, а не название «Ягода», её тексты, фирменные цвета или маникюрную тематику.

Для персональных демо потенциальным клиентам создавайте отдельный самодостаточный каталог `prospects/<slug>/` для каждого салона: копируйте основу из `yagoda-copy/`, затем меняйте только подходящие конкретному клиенту бренд, визуал и подтверждённые услуги/цены. Если пользователь просит опубликовать демо, публикуйте выбранные папки через настроенный GitHub Pages workflow и после успешной проверки отдавайте прямые ссылки на каждую страницу. Не называйте локальный макет официальным сайтом студии.

Перед завершением каждой демо-версии проверьте её на широком и мобильном экранах, клавиатурой и на состояниях ошибок/пустых данных/успешного действия. Убедитесь, что кнопки и ссылки работают, нет горизонтального переполнения, виден фокус, а анимации уважают `prefers-reduced-motion`. Все демонстрационные данные и ограничения локального хранения обозначайте прямо; не обещайте реальную отправку заявок или серверные функции, если их нет. Не объявляйте проверки выполненными, пока действительно их не провели.

## Запуск и проверка

Откройте `index.html` в актуальном браузере. Для локального HTTP-сервера без установки зависимостей можно выполнить из корня:

```powershell
python -m http.server 8000
```

Затем откройте `http://localhost:8000`. Для ручной проверки используйте широкую и телефонную ширину, клавиатурную навигацию, карточки мастеров, переключение месяцев, занятые слоты, подтверждение и форму отзыва после визита. Записи, профиль и отзывы хранятся в `localStorage` этого браузера; аккаунта и серверного хранилища нет. В проекте пока нет автоматических тестов или команд сборки.

## Стиль и изменения

Сохраняйте русский язык интерфейса, семантические HTML-элементы, видимый фокус и мобильную доступность. Используйте два пробела для отступов в HTML, CSS и JavaScript; имена CSS-классов пишите в kebab-case, переменные и функции JavaScript — в camelCase. Общие стили и цвета задавайте через токены в `:root`; не добавляйте зависимость ради простого эффекта. Анимации должны уважать `prefers-reduced-motion`.

Перед назначением цветов проверяйте контраст текста и его фактического фона во всех состояниях компонента: обычном, наведённом, выбранном и отключённом. Для обычного текста ориентируйтесь на WCAG AA — не менее 4.5:1; для крупного текста — не менее 3:1. Проверяйте также подписи, бейджи и текст поверх изображений.

Все цены, имена, стаж, работы, расписание, занятость, отзывы, адрес и контакты являются условными. Ясно обозначайте демо-данные; записи и отзывы сохраняются только в `localStorage` текущего браузера и не видны другим посетителям. Не представляйте этот сценарий как рабочую запись клиента или общий backend.

## Коммиты и pull request

В доступной Git-истории нет образцов, поэтому это рекомендация, а не установленная конвенция: используйте короткий глагольный заголовок на русском, например `Добавить выбор времени`. В PR опишите пользовательское изменение и ручные проверки; для визуальных правок приложите скриншот мобильного и широкого экранов. Не включайте клиентские данные или секреты.
